Pytest suite for the claude-plugins-kit bridge, compatibility analysis, migration, maintenance, runtime, and native Codex lifecycle.

    This is the pytest suite for the plugin bridge that carries Claude plugins and personal skills into Codex. The test files split one per subsystem: discovery and sync, compatibility analysis, migration, maintenance, runtime, and the native app-server lifecycle. Most tests drive an in-memory fake of the codex CLI, so a bare run needs no network and no installation. A handful of tests sit behind opt-in environment variables and cover live inference, a real runtime download, and a full native Codex session. Because the fixtures load the plugin's own scripts by path instead of a copy, a failure points at the code that ships.

    Where to start

    Start with conftest.py. It loads the shipped bridge and migration scripts straight from their files and hands them to the suite as session fixtures, so it is the shortest way to learn what every other file is actually testing.

    Routes

    • Trace a sync behavior change: conftest.py -> test_bridge.py -> test_maintenance.py. The middle file holds the discovery, sync, and fail-closed cases; the last one imports its fake runner and fixtures, so a broken handoff surfaces as a maintenance failure.
    • Chase a migration bug: test_migration.py -> test_native_lifecycle.py. The first covers the journal, backup, resume, and drift rules around the legacy files; the second replays the cleanup inside a live Codex home.
    • Find what a bare run skips: test_compatibility.py -> test_consumer_runtime.py -> test_native_lifecycle.py. Each gates its heavy tests behind an opt-in variable: a live inference smoke check, a real runtime download, and the full native lifecycle.

    Bridge discovery, sync, and maintenance

    • test_bridge.py - Executable discovery (an environment override beats PATH, and the newest Windows install wins), frontmatter parsing, and the sync pass with its fail-closed races. The largest file, and home of the fake runner the maintenance tests import.
    • test_maintenance.py - Release-check throttling and cooldown, marketplace trust rules, candidate validation, and lock contention. Open it when a maintain run warns, throttles, or refuses to upgrade.

    Compatibility analysis

    • test_compatibility.py - Requirement extraction with source evidence, capability mapping, inference policy and cache rules, and report identity. Open it when a report field looks wrong, or to check that a failed inference never reads back as a cache hit.

    Migration off the legacy plugins-kit

    • test_migration.py - The cleanup of the old plugins-kit hooks, stubs, and state files: journal, backup, resume, and drift checks, with a read-only preview. A failed install must leave every legacy byte untouched.
    • test_native_lifecycle.py - The same install, sync, migrate, and uninstall flow against a live codex binary, with the catalog read back through the app-server. Skipped unless its opt-in variable is set and codex is on PATH.

    Runtime resolution and provisioning

    • test_runtime.py - What the runtime info exposes and withholds: declared venv spelling, ambiguous or escaped paths, advisory findings for missing, stale, or invalid reports, and disclosure dedup within a session.
    • test_consumer_runtime.py - The POSIX launcher with no Python present: it refuses unsafe data roots before writing, rejects a corrupt download, and releases its lock for a retry. The real download test is opt-in, and the whole file is POSIX-only.

    Fixtures and installed-artifact shape

    • conftest.py - Loads the shipped bridge and migration scripts by path and exposes them as session fixtures. Open it first when a test's imports look magic.
    • test_hooks_and_manifests.py - Pins the cross-platform hook commands, the match between the authored manifest and marketplace names, and the SessionStart output shape the host reads.
